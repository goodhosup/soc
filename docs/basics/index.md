# 공통 기초

이 섹션은 CPU·GPU·메모리 같은 개별 블록으로 들어가기 전에, **모든 블록에 공통으로 적용되는 물리와 구조**를 다룹니다. 트랜지스터가 왜 전력을 쓰는지, 공정 노드 이름이 무엇을 뜻하는지, 캐시가 왜 필요한지, 블록끼리 어떻게 연결되는지를 알면 이후 장의 거의 모든 설계 결정을 "왜 그렇게 했나"로 읽을 수 있습니다.

| 페이지 | 핵심 질문 |
|---|---|
| [트랜지스터와 CMOS](transistor.md) | 디지털 회로는 왜 스위칭할 때 전력을 쓰고, 가만히 있어도 전력이 새나? |
| [공정 노드와 미세화](process-node.md) | "3nm"는 무엇의 길이인가? 평면 → FinFET → GAA로 바뀐 이유는? |
| [컴퓨터 구조 기초](computer-architecture.md) | 명령어 집합, 파이프라인, 슈퍼스칼라, 비순차 실행은 성능을 어떻게 올리나? |
| [메모리 계층](memory-hierarchy.md) | 레지스터부터 UFS까지, 속도와 용량이 왜 반비례하고 캐시는 어떻게 그 틈을 메우나? |
| [클럭과 전압](clock-voltage.md) | 클럭 도메인·전압 도메인은 무엇이고, 동적 전력 공식은 설계에 무엇을 말해 주나? |
| [버스와 인터커넥트](interconnect.md) | AMBA AXI·ACE·CHI와 NoC는 블록들을 어떻게 잇나? |
| [성능·전력·면적 (PPA)](ppa.md) | 칩 설계의 세 가지 목표는 왜 서로 부딪히고, 면적은 왜 곧 비용인가? |

!!! basic "이 섹션의 세 가지 숫자"
    공통 기초 전체를 관통하는 숫자 세 가지만 기억해도 이후 장이 훨씬 쉽게 읽힙니다.

    1. **전력은 전압의 제곱에 비례** — \(P \propto V^2 f\). 전압을 낮추는 기술(DVFS, 미세 공정)이 전력 절감의 핵심입니다.
    2. **DRAM 접근은 L1 캐시보다 약 100배 느림** — 수 GHz 코어에게 DRAM 한 번 다녀오는 시간은 수백 사이클입니다. 캐시와 SLC가 성능을 좌우하는 이유입니다.
    3. **다이 면적은 곧 비용** — 같은 웨이퍼에서 나오는 칩 수와 수율이 면적에 따라 결정됩니다.

!!! tip "다른 섹션과의 연결"
    동적 전력 공식의 실제 활용은 [DVFS와 전력 관리](../power/dvfs.md), 캐시의 구체적인 구성은 [캐시와 일관성](../cpu/cache-coherence.md)과 [메모리 컨트롤러와 SLC](../memory/controller-slc.md), 공정의 회사별 비교는 [파운드리와 공정](../design/foundry.md)에서 다룹니다.
