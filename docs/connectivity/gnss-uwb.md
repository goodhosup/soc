# GNSS·UWB·위성

!!! spec "규격 · 세대"
    GNSS: GPS L1 C/A·**L5**, Galileo E1·**E5a**, BeiDou B1·**B2a**, QZSS, NavIC · UWB: **IEEE 802.15.4z**(2020, 보안 거리 측정 강화), FiRa Consortium 상호 운용 규격, CCC 디지털 키 · 위성: **3GPP Rel-17 NTN**(NR-NTN, IoT-NTN) → Rel-18 이후 확장
    스마트폰 적용: 이중 주파수 GNSS는 2018년형 기기(외장 Broadcom BCM47755 탑재 기기)에서 처음 등장 → 이후 SoC 내장 GNSS로 확산 · UWB는 iPhone 11(2019, Apple U1)과 Galaxy Note20 Ultra(2020)부터 · 위성 긴급 메시지는 iPhone 14(2022, 독자 방식)부터, 3GPP NTN 기반은 2024년형 기기부터

!!! basic "한눈에 보기"
    이 페이지의 세 기술은 모두 **"나는 어디에 있나, 무엇과 얼마나 떨어져 있나"**에 관한 것입니다.

    1. **GNSS** — 하늘의 위성들이 보내는 시각 신호를 받아, 신호가 도착한 시간 차이로 내 위치를 계산합니다. 수신만 하므로 위성에 아무것도 보내지 않습니다.
    2. **UWB** — 아주 넓은 주파수 폭을 쓰는 짧은 펄스로, 근처 기기까지의 거리와 방향을 수십 cm 이하 수준으로 잽니다. 차 키, 분실물 찾기에 씁니다.
    3. **위성 통신** — 기지국이 없는 곳에서 위성과 직접 짧은 메시지를 주고받습니다. GNSS와 달리 휴대폰이 위성으로 **송신**해야 해서 훨씬 어렵습니다.

    비유하면 GNSS는 여러 방향의 시계탑 종소리로 위치를 짐작하는 것, UWB는 줄자로 옆 사람과의 거리를 재는 것, 위성 통신은 멀리 있는 산 정상의 사람에게 손전등으로 신호를 보내는 것입니다.

## GNSS: 이중 주파수와 SoC 안의 위치 { .l2 }

| 항목 | L1 대역 (L1·E1·B1) | L5 대역 (L5·E5a·B2a) |
|---|---|---|
| 중심 주파수 | 1575.42 MHz | 1176.45 MHz |
| 특징 | 모든 수신기가 지원하는 기본 신호 | 더 긴 확산 부호, 더 넓은 대역폭 |
| 도심 다중 경로 | 반사파와 직접파 구분이 상대적으로 어려움 | 반사파를 더 잘 구분 |
| 전리층 지연 | 기준 | L1의 약 1.79배 (주파수 제곱에 반비례) |

전리층 지연이 주파수의 제곱에 반비례하므로, 두 주파수의 측정값을 함께 쓰면 지연을 거의 지울 수 있습니다. L1 대비 L5의 지연 비는 (1575.42 / 1176.45)² ≈ **1.79**입니다. (수치는 `tools/soc_numbers.py`에서 계산)

| 구성 요소 | 일반적인 위치 |
|---|---|
| GNSS RF 수신부 | 셀룰러 RF 트랜시버에 함께 들어가거나 별도 GNSS 칩 |
| GNSS 베이스밴드 (상관기·추적) | SoC 안의 전용 블록 (모뎀 서브시스템 근처에 두는 경우가 많음) |
| 위치 계산 엔진 | GNSS 서브시스템 펌웨어 또는 AP 소프트웨어 |
| 센서 융합·지오펜싱 | 저전력 센서 허브에서 처리해 AP를 깨우지 않음 ([센서 허브](../media/sensor-hub.md)) |

## UWB: 거리와 방향 측정 { .l2 }

| 항목 | 내용 |
|---|---|
| 주파수 | 채널 5(약 6.5 GHz), 채널 9(약 8 GHz)가 스마트폰에서 주로 쓰임 |
| 대역폭 | 채널당 499.2 MHz |
| 측정 원리 | 신호 왕복 시간(ToF)으로 거리, 여러 안테나의 위상 차(AoA)로 방향 |
| 시간 해상도 | 샘플 하나의 시간 동안 빛은 약 0.60 m 이동 (보간으로 그보다 훨씬 정밀하게 측정) |
| SoC와의 연결 | 주로 SPI, 깨우기·인터럽트용 GPIO |
| 보안 | 802.15.4z의 STS(Scrambled Timestamp Sequence)로 거리 위조 방지, 키는 보안 요소에서 관리 |

0.60 m는 빛의 속도 ÷ 499.2 MHz로 계산한 값입니다. (수치는 `tools/soc_numbers.py`에서 계산) 스마트폰 UWB는 대부분 **별도 칩**이며, Apple은 자체 설계 칩(U1, 이후 2세대 UWB 칩), Android 기기는 NXP·Qorvo 같은 전문 업체 칩을 써 왔습니다. 최근에는 UWB를 Wi-Fi·Bluetooth 콤보 칩에 합치는 제품도 발표되었습니다(예: Qualcomm FastConnect 7900, 2024년 발표).

## 위성 통신의 세 가지 방식 { .l2 }

| 방식 | 내용 | 휴대폰 쪽 요구 |
|---|---|---|
| 독자 방식 | 특정 위성 사업자와 전용 프로토콜 (예: Apple의 긴급 SOS, Globalstar) | 모뎀·RF가 해당 대역과 프로토콜을 지원하도록 맞춤 설계 |
| 3GPP NTN (모뎀 내장) | Rel-17의 IoT-NTN(NB-IoT 기반)·NR-NTN을 모뎀이 지원, 저속 메시지 위주 | 모뎀 펌웨어·RF 대역 지원, 도플러·지연 보상 |
| 위성 직접 셀룰러 | 위성이 지상 기지국처럼 기존 LTE 대역으로 송수신 | 기존 단말 그대로 (위성 쪽이 보상) |

이 페이지 기준 시점에 3GPP NTN을 지원하는 휴대폰 모뎀으로는 Samsung Exynos Modem 5400(Pixel 9의 위성 SOS), Qualcomm Snapdragon X80(NB-NTN 지원 발표), MediaTek의 IoT-NTN 칩 등이 알려져 있습니다.

??? expert "전문가 노트 — 원시 GNSS 측정, 기준 클럭, UWB 보안 거리 측정, NTN의 지연 보상"
    **원시 GNSS 측정.** Android는 7.0부터 의사거리·도플러·반송파 위상 같은 **원시 GNSS 측정값**을 앱에 공개하는 API를 제공합니다. 이중 주파수 반송파 위상까지 얻을 수 있는 기기에서는 정밀 측위(정밀 단독 측위·RTK 계열) 연구가 가능하지만, 스마트폰 안테나는 작고 선형 편파이며 몸에 가려지기 쉬워 측량용 수신기만큼의 정확도는 기대하기 어렵습니다. 칩에 따라 반송파 위상 연속성(사이클 슬립 처리)이나 측정 제공 범위가 다릅니다.

    **기준 클럭과 첫 위치 시간.** GNSS 수신기는 매우 안정된 기준 클럭이 필요해, 셀룰러 모뎀과 같은 수정 발진기(TCXO 또는 XO + 온도 보정)를 공유하는 경우가 많습니다. 모뎀이 기지국 신호로 클럭 오차와 대략적인 위치·시각을 알려 주면(보조 GNSS), 위성 탐색 범위가 크게 줄어 첫 위치 획득 시간과 전력이 줄어듭니다. 모뎀과 GNSS를 같은 회사·같은 서브시스템에 두는 이유 중 하나입니다.

    **UWB 보안 거리 측정.** 거리 측정이 차 문을 여는 열쇠가 되면, 공격자가 신호를 중계하거나 미리 보내 "가까운 척"하는 공격을 막아야 합니다. 802.15.4z는 양쪽이 공유한 키로 만든 STS를 펄스 열에 넣어, 키를 모르면 첫 도착 경로를 위조하기 어렵게 합니다. 키 교환은 Bluetooth LE 같은 다른 경로로 하고, 키 자체는 보안 요소(eSE)나 TEE에서 관리합니다([하드웨어 보안 모듈](../security/secure-element.md)).

    **NTN의 지연 보상.** 저궤도 위성은 초속 수 km로 움직여 도플러 이동이 크고, 왕복 지연이 지상 셀보다 훨씬 깁니다. Rel-17 NTN 단말은 **자신의 GNSS 위치**와 위성이 방송하는 궤도 정보로 송신 시각과 주파수를 미리 보정합니다. 그래서 NTN 모뎀은 GNSS 서브시스템과 긴밀하게 협력해야 하며, 휴대폰 안테나의 낮은 이득 때문에 송신 전력과 전송 시간을 아끼는 짧은 메시지 위주로 설계됩니다([Cellular Handbook](https://goodhosup.github.io/cellular/)).

| 항목 | Qualcomm Snapdragon | Samsung Exynos | MediaTek Dimensity | Apple | Google Tensor |
|---|---|---|---|---|---|
| GNSS | SoC 내장, 이중 주파수 지원 (플래그십) | SoC 내장 GNSS (모델별) | SoC 내장, 이중 주파수 지원 (플래그십) | 이중 주파수 지원 (Pro 모델부터 확산) | 외장 GNSS 칩 사용으로 알려짐 |
| UWB | 외장 칩 조합 → 콤보 칩 통합 발표 | 외장 칩 (NXP 등), 자체 UWB 칩(Exynos Connect U100) 발표 | 외장 칩 조합 | 자체 UWB 칩 | 외장 칩 (분해 분석 기준) |
| 위성 메시지 | 모뎀의 NB-NTN 지원 (X80 이후 발표 기준) | Exynos 모뎀의 NTN 지원 | IoT-NTN 칩·모뎀 | 독자 방식 (Globalstar) | Exynos 모뎀의 NTN (위성 SOS) |
