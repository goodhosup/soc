# Arm 아키텍처

!!! spec "규격 · 세대"
    Arm Architecture Reference Manual for A-profile (Arm ARM) · Armv8-A(2011 발표, 64비트 **AArch64** 도입) → v8.x 확장(원자 연산, FP16, 포인터 인증, MTE 등) → **Armv9-A**(2021 발표, SVE2 기본 포함) → v9.x 확장(SME·SME2, 기밀 컴퓨팅 RME 등)
    스마트폰 적용: 첫 64비트 스마트폰 SoC는 2013년 Apple A7, Android 플래그십은 2015년 무렵 64비트 전환, Armv9 코어는 2022년형 플래그십부터

!!! basic "한눈에 보기"
    **아키텍처**는 "CPU가 알아듣는 말"을 정한 약속이고, **코어**는 그 말을 알아듣도록 실제로 만든 회로입니다.

    1. Arm은 이 약속(Arm 아키텍처)을 문서로 정하고 다른 회사에 사용권을 팝니다.
    2. 같은 아키텍처를 지키는 코어라면 누가 만들었든 같은 프로그램이 돌아갑니다. Snapdragon과 Exynos와 Apple 칩에서 같은 Android·iOS 앱 코드가 도는 이유입니다.
    3. 아키텍처는 몇 년마다 **버전**(v8, v9)이 오르고, 그 사이사이 **확장 기능**(v8.2, v9.2 같은 점 버전)이 추가됩니다.

    건축에 비유하면 아키텍처는 "문 높이, 콘센트 모양, 계단 규격"을 정한 건축 법규이고, 코어는 그 법규를 지켜 지은 실제 건물입니다. 같은 법규를 지킨 건물이라도 크기와 내부 구조는 천차만별입니다.

## 아키텍처 버전의 흐름 { .l2 }

| 버전 | 주요 내용 | 의미 |
|---|---|---|
| ARMv7-A | 32비트, NEON SIMD, 가상화 확장 | 2010년대 초반 스마트폰의 표준 |
| **Armv8-A** | **AArch64**(64비트 실행 상태, 범용 레지스터 31개), A64 명령어 집합, 예외 수준 EL0–EL3 정리, 암호 명령 | 64비트 전환 |
| v8.1 | LSE 원자 연산 | 멀티코어 동기화 성능 |
| v8.2 | FP16 연산, 내적(dot product) 명령(선택), RAS | 머신러닝 연산 가속의 시작 |
| v8.3 | **포인터 인증(PAC)** | 반환 주소 위조 공격 방어 |
| v8.5 | **MTE**(메모리 태깅), BTI(분기 대상 식별) | 메모리 안전성 버그 탐지, 코드 재사용 공격 방어 |
| v8.6 | BF16, INT8 행렬 곱(I8MM) | AI 추론 가속 |
| **Armv9-A** | **SVE2**를 기본 포함, 트레이스 개선 | 가변 길이 벡터, 다음 10년의 기준선 |
| v9.x | **SME·SME2**(행렬 확장), RME(기밀 컴퓨팅 영역) 등 | CPU에서의 행렬 연산, 보안 격리 강화 |

점 버전의 기능 중 상당수는 **선택(optional)**입니다. "Armv9.2 코어"라고 해도 모든 선택 기능을 구현했다는 뜻은 아니므로, 소프트웨어는 실행 중에 기능 레지스터(`ID_AA64*`)나 운영체제가 알려 주는 기능 목록(Linux의 `HWCAP`, `/proc/cpuinfo`의 Features)으로 확인해야 합니다.

## 예외 수준과 실행 상태 { .l2 }

| 예외 수준 | 실행하는 것 | 예 |
|---|---|---|
| EL0 | 사용자 앱 | Android 앱, 시스템 서비스 |
| EL1 | 운영체제 커널 | Linux 커널 |
| EL2 | 하이퍼바이저 | Android pKVM, 벤더 하이퍼바이저 |
| EL3 | 보안 모니터 (보안 세계 전환) | Trusted Firmware-A 같은 펌웨어 |

![Arm 예외 수준 EL0–EL3과 일반 세계·보안 세계의 구성](../assets/figures/cpu_exception_levels.svg)

여기에 **보안 세계(Secure)**와 **일반 세계(Non-secure)**라는 축이 겹쳐, 보안 세계의 EL1에서 TEE 운영체제가, EL0에서 신뢰 앱(TA)이 돕니다([TrustZone과 TEE](../security/trustzone.md)).

## 주요 확장이 하는 일 { .l2 }

| 확장 | 하는 일 | 쓰는 곳 |
|---|---|---|
| NEON (Advanced SIMD) | 128비트 고정 폭 벡터 연산 | 미디어·이미지 처리, 문자열 처리, 기존 최적화 코드 대부분 |
| SVE2 | 구현마다 길이가 다를 수 있는 벡터 + 술어(predicate) 기반 연산 | 같은 코드로 여러 벡터 폭 대응, 복잡한 루프 벡터화 |
| SME·SME2 | 행렬 타일 레지스터와 외적(outer product) 연산, 스트리밍 모드 | CPU 위의 행렬 곱, 소규모 AI 추론 |
| 암호 확장 | AES, SHA, 다항식 곱 명령 | TLS, 저장장치 암호화 |
| PAC·BTI | 포인터 서명, 분기 대상 표시 | 제어 흐름 탈취 공격 방어 |
| MTE | 메모리 4비트 태그와 포인터 태그 비교 | 메모리 오류(버퍼 넘침, 해제 후 사용) 탐지 |

??? expert "전문가 노트 — 32비트의 퇴장, SVE2 폭, SME 스트리밍 모드, 라이선스와 호환성"
    **AArch32의 퇴장.** Arm은 2021년 이후 고성능 코어부터 AArch32 실행 지원을 빼기 시작했고, 이후 세대 코어는 64비트 전용으로 갔습니다. 32비트 지원을 빼면 디코더·레지스터 매핑 회로를 줄일 수 있습니다. Android도 64비트 전용 시스템 이미지로 이동했으므로, 오래된 32비트 전용 앱은 최신 기기에서 실행되지 않을 수 있습니다.

    **SVE2 폭 128비트의 의미.** SVE2는 128–2048비트 사이에서 구현이 폭을 고를 수 있지만, 현재 모바일 코어 구현은 128비트가 일반적인 것으로 알려져 있습니다. 같은 폭이라면 NEON 대비 연산량 이득은 없고, 술어 레지스터 덕분에 루프 끝 처리·조건부 연산을 벡터화하기 쉬워지는 표현력 이득이 큽니다. 코드는 `svcntb()` 같은 함수로 실행 시점의 벡터 길이를 읽어 쓰므로, 폭이 늘어난 미래 코어에서 다시 컴파일하지 않아도 이득을 봅니다.

    **SME의 스트리밍 모드.** SME 명령은 일반 실행과 다른 **스트리밍 SVE 모드**에서 실행되며, 이 모드에서는 벡터 길이가 코어 기본 SVE 길이와 다를 수 있고 사용 가능한 명령도 제한됩니다. 구현에 따라 행렬 유닛이 여러 코어가 공유하는 별도 블록일 수 있어, 모드 전환 비용과 공유 경합을 고려해야 합니다. Apple M4 세대와 2025년형 Arm C1 계열 코어가 SME 계열을 지원하는 것으로 발표되었습니다.

    **아키텍처 라이선스와 호환성 시험.** 직접 코어를 설계한 회사도 아키텍처 준수 시험(Arm 아키텍처 준수 스위트)을 통과해야 Arm 호환 코어라고 부를 수 있습니다. 덕분에 자체 코어와 Cortex 코어가 섞인 생태계에서도 같은 바이너리가 동작합니다. 다만 성능 특성(어떤 명령이 빠른가)은 코어마다 다르므로, 라이브러리는 코어별 튜닝 경로를 따로 두기도 합니다.

## 칩셋 비교

| 항목 | Arm 코어 사용 칩 (Exynos, Dimensity, Tensor) | 자체 코어 칩 (Apple, Snapdragon Oryon) |
|---|---|---|
| 아키텍처 버전 | 사용한 Arm 코어 세대가 정함 | 자체 설계가 정함 (확장 기능 선택 폭 넓음) |
| 확장 기능 확인 | Arm 코어 기술 문서로 확인 가능 | 회사 발표·실측(`HWCAP`) 위주 |
| 최신 확장 도입 시점 | Arm 코어 출시 주기에 맞춰 | 회사 일정에 따라 빠르거나 늦을 수 있음 |
