# Arm 코어 계보

!!! spec "규격 · 세대"
    Arm 코어 기술 참조 설명서(Technical Reference Manual), Arm 발표 자료 · 아키텍처: Armv8-A(Cortex-A53·A57부터) → v8.2(A75·A55, DynamIQ) → **Armv9.0**(X2·A710·A510, 2021) → v9.2(X4·A720·A520, 2023) → **C1 계열**(2025, Armv9.3) → C2 계열(2026, Armv9.3 기반)
    연도는 Arm이 코어를 **발표한 해** 기준이며, 탑재 스마트폰은 보통 그다음 해에 나옵니다.

!!! basic "한눈에 보기"
    Arm은 매년 비슷한 시기에 새 CPU 코어를 발표하고, SoC 회사들은 이를 사서 다음 해 칩에 넣습니다. 코어는 크게 **세 등급**으로 나뉩니다.

    1. **최고 성능 코어** — 크고 빠르고 전력을 많이 씀. Cortex-X 계열 → C1-Ultra
    2. **균형 코어** — 성능과 효율의 중간. Cortex-A7xx 계열 → C1-Premium·C1-Pro
    3. **고효율 코어** — 작고 느리지만 전력을 아주 적게 씀. Cortex-A5xx 계열 → C1-Nano

    한 칩은 이 등급의 코어를 섞어 클러스터를 만듭니다([이기종 클러스터](clusters.md)). 같은 해에 나온 Exynos와 Dimensity가 같은 이름의 코어를 쓰는 일이 흔한 것도 이 때문입니다.

## 세대별 코어 { .l2 }

| 발표 연도 | 최고 성능 | 균형 | 고효율 | 아키텍처 | 비고 |
|---|---|---|---|---|---|
| 2012 | — | Cortex-A57 | Cortex-A53 | Armv8.0 | 첫 Armv8 코어 쌍 |
| 2015–2016 | — | A72 → A73 | A53 | Armv8.0 | |
| 2017 | — | A75 | **A55** | Armv8.2 | **DynamIQ** 도입, A55는 이후 여러 해 사용 |
| 2018–2019 | — | A76 → A77 | A55 | Armv8.2 | 노트북급 성능을 목표로 한 A76 |
| 2020 | **Cortex-X1** | A78 | A55 | Armv8.2 | 고객 맞춤 고성능 코어 프로그램(Cortex-X) 시작 |
| 2021 | X2 | A710 | **A510** | **Armv9.0** | Armv9 첫 세대 |
| 2022 | X3 | A715 | A510 (개선판) | Armv9.0 | 고성능 코어 64비트 전용화 진행 |
| 2023 | X4 | A720 | A520 | Armv9.2 | |
| 2024 | X925 | A725 | A520 (개선판) | Armv9.2 | 이름 체계 변경(X925) |
| 2025 | **C1-Ultra** | **C1-Premium · C1-Pro** | **C1-Nano** | Armv9.3 | 브랜드 개편, SME2 지원, **Lumex** 플랫폼 |
| 2026 | C2-Ultra | C2-Pro | — | Armv9.3 (일부 v9.4 기능, 발표 기준) | CSS for Mobile 2로 발표, Lumex 이름은 쓰지 않음, 고효율 등급 코어 없이 발표 |

함께 쓰는 클러스터 부품인 **DSU**(DynamIQ Shared Unit)도 세대를 거듭하며 코어 수·L3 용량·전력 관리 기능을 늘려 왔습니다([캐시와 일관성](cache-coherence.md)).

## 등급별 설계 성격 { .l2 }

| 항목 | 최고 성능 (X·C1-Ultra) | 균형 (A7xx·C1-Premium/Pro) | 고효율 (A5xx·C1-Nano) |
|---|---|---|---|
| 실행 방식 | 매우 넓은 비순차 실행 | 중간 폭 비순차 실행 | 순차 실행 위주 |
| 목표 | 단일 스레드 최고 성능 | 성능/W 최적점 | 최저 전력·작은 면적 |
| 전용 L2 | 크게 (MB 단위) | 중간 | 작거나 두 코어가 공유하는 구성 |
| 사용처 | 앱 실행 직후, 웹 페이지 로드, 게임 주 스레드 | 일반 앱, 멀티스레드 작업 | 백그라운드, 알림, 음악 재생 |
| 칩당 개수 | 1–2개 (일부 칩은 더 많음) | 3–7개 | 0–4개 |

## 고객 맞춤 프로그램과 CSS { .l2 }

| 구분 | 내용 |
|---|---|
| Cortex-X 프로그램 (2020~) | 고객의 성능 요구를 반영해 면적·전력 제약을 완화한 고성능 코어. 면적이 크게 늘더라도 단일 스레드 성능을 최우선 |
| 구성 옵션 | 같은 코어라도 L2 크기, 캐시 ECC, 일부 선택 기능을 고객이 정함 → 같은 코어 이름이어도 칩마다 성능이 다름 |
| CSS (Compute Subsystem) | 코어·DSU·인터커넥트·물리 구현 참고까지 묶어 제공. 개발 기간 단축, 대신 차별화 여지 감소 |

??? expert "전문가 노트 — 같은 코어, 다른 성능 / 작은 코어의 위기 / 이름 개편의 의미"
    **같은 코어, 다른 성능.** 같은 Cortex-X 코어를 쓴 두 SoC의 성능·효율이 크게 다른 이유는 ① L2 크기 선택, ② 공정과 셀 라이브러리(고성능 셀 vs 고밀도 셀), ③ 최대 클럭과 전압, ④ L3·SLC·메모리 서브시스템의 지연, ⑤ 전력 관리 정책 때문입니다. 코어 IP는 같아도 물리 구현이 다르면 사실상 다른 제품입니다.

    **작은 코어의 위기.** A55는 2017년부터 2021년까지 여러 세대 동안 고효율 코어 자리를 지켰고, 후속 A510·A520은 성능을 올린 대신 면적·전력도 늘었습니다. 이 무렵부터 일부 SoC가 고효율 코어 수를 줄이거나(예: 2개), 아예 빼고 균형·고성능 코어만으로 구성(Dimensity 9300의 빅 코어 8개 구성 등)하기 시작했습니다. 실제 워크로드의 에너지 측정에서 "균형 코어를 낮은 클럭으로" 돌리는 편이 작은 코어와 큰 차이가 없거나 낫다는 판단이 반영된 것으로 해석됩니다.

    **세대 사이의 개선판.** Arm은 같은 코어 이름으로 리비전(r0p0, r1p0 …)을 내며 전력 효율이나 버그를 개선합니다. 커널 소스의 errata 워크어라운드 목록(`arch/arm64/kernel/cpu_errata.c`)이 코어·리비전별로 정리되어 있어, 실제 칩이 어떤 리비전을 쓰는지 확인할 때 참고할 수 있습니다. 커널은 `MIDR_EL1` 레지스터의 부품 번호로 코어 종류를 식별합니다.

    **이름 개편의 의미.** 2025년의 C1 계열 개편은 CPU·GPU·플랫폼(Lumex) 이름을 한 체계로 묶은 것입니다. 이름보다 중요한 것은 등급 구조가 기존 세 등급에서 C1-Ultra·Premium·Pro·Nano의 네 이름으로 세분화되었다는 점이며, 칩 회사가 성능·면적 목표에 맞춰 더 다양한 조합을 고를 수 있게 되었습니다.

## 칩셋 비교

| 항목 | Exynos | Dimensity | Tensor | Snapdragon (참고) |
|---|---|---|---|---|
| Arm 최신 코어 채택 | 대체로 같은 해 Arm 코어 사용 | 최신 코어를 빠르게 채택하는 편 | 한 세대 늦은 코어를 쓰는 경우가 있음 | 현재는 자체 코어(Oryon), 이전 세대는 Arm 코어 기반 Kryo |
| 특징적 구성 | 10코어 구성 등 다양한 시도 | 빅 코어 위주 구성 | 균형 중심 | 2+6 구성 |
