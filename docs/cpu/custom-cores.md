# 자체 설계 코어

!!! spec "규격 · 세대"
    Arm 아키텍처 라이선스(명령어 집합 사용권)로 설계한 코어 · 아키텍처 준수는 Arm 아키텍처 준수 시험으로 확인
    Apple: A6(2012)부터 자체 코어 · Qualcomm: Scorpion·Krait(자체) → Kryo(초기 자체, 이후 Arm 코어 기반) → **Oryon**(Nuvia 인수 후, 2024년 PC용 Snapdragon X와 스마트폰용 Snapdragon 8 Elite) · 삼성: Mongoose(2016–2020 세대, 이후 개발 중단)

!!! basic "한눈에 보기"
    Arm에게서 "완성된 코어"를 사지 않고, **명령어 집합 사용권만 사서 코어를 직접 설계**하는 회사들이 있습니다.

    1. **장점** — 자기 제품에 꼭 맞게 코어를 설계할 수 있습니다. 성능 목표, 전력, 캐시 구조, 운영체제와의 협력까지 마음대로 정합니다.
    2. **단점** — 코어 하나를 설계하는 데 수백 명 규모의 팀과 여러 해가 걸리고, 매년 Arm의 새 코어보다 나은 결과를 내야 의미가 있습니다.

    맞춤 양복과 기성복에 비유하면, Arm 코어는 잘 만든 기성복이고 자체 코어는 맞춤 양복입니다. 맞춤이 몸에 더 잘 맞지만, 재단사를 계속 고용하고 매년 새 옷을 지어야 합니다.

## 주요 자체 코어의 흐름 { .l2 }

| 회사 | 코어 | 시기 | 특징 |
|---|---|---|---|
| **Apple** | Swift(A6) → Cyclone(A7, 첫 64비트) → … → Firestorm·Icestorm(A14·M1) → 이후 세대 | 2012~ | 넓은 디코드·대형 재정렬 버퍼, 비교적 낮은 클럭에서 높은 IPC. iPhone과 Mac이 같은 코어 계열 공유 |
| **Qualcomm** | Scorpion → Krait → Kryo(Snapdragon 820) | 2008–2016 | 초기 스마트폰 시대의 자체 코어 |
| Qualcomm | Kryo (Arm Cortex 기반) | 2017–2023 | Arm 코어를 일부 조정해 Kryo 이름으로 사용 |
| **Qualcomm** | **Oryon** | 2024~ | Nuvia(서버 CPU 스타트업) 인수 후 개발. PC(Snapdragon X)와 스마트폰(Snapdragon 8 Elite 이후) 공유 |
| 삼성 | Mongoose M1–M5 | 2016–2020 세대 | Exynos 플래그십에 탑재, 전력 효율 문제 끝에 개발 중단, 이후 Arm 코어로 복귀 |
| NVIDIA | Denver | 2014~ | 하드웨어 디코더와 동적 코드 최적화를 결합한 독특한 설계 (모바일에서는 짧게 사용) |

## Arm 코어 ↔ 자체 코어 { .l2 }

| 항목 | Arm 코어 (Cortex·C1) | 자체 코어 |
|---|---|---|
| 개발 기간 | Arm이 개발, SoC 회사는 통합만 (1–2년) | 자체 개발 (여러 해, 여러 세대 병렬) |
| 차별화 | 구성 옵션, 물리 구현, 클럭으로만 | 마이크로아키텍처 전체 |
| 클러스터 구조 | DSU 기반, 코어 전용 L2 + 공유 L3 | 회사 고유 (예: 클러스터 공유 대형 L2) |
| 비용 | 라이선스 비용 + 로열티 | 설계 조직 비용 + 아키텍처 라이선스 |
| 공개 정보 | 기술 참조 설명서 공개 | 공개 정보 적음, 분석 위주 |
| 위험 | 경쟁사와 같은 코어 → 차별화 어려움 | 한 세대 실패가 제품 경쟁력에 직결 |

## 자체 코어가 잘하는 것 { .l2 }

| 영역 | 예 |
|---|---|
| 넓은 코어 + 낮은 클럭 | 같은 성능을 더 낮은 전압에서 내어 전력 효율 확보 |
| 큰 공유 캐시 | 클러스터 공유 L2를 10 MB 이상으로 키워 메모리 지연 숨김 |
| 운영체제와의 통합 | 하드웨어 성능 컨트롤러와 OS 스케줄러의 긴밀한 협력 (Apple) |
| 제품군 공유 | 같은 코어를 스마트폰·태블릿·노트북에 공유해 개발비 분산 (Apple, Qualcomm) |

??? expert "전문가 노트 — Mongoose의 교훈, Oryon의 클러스터, 자체 코어 평가 방법"
    **Mongoose의 교훈.** 삼성 Mongoose는 세대마다 코어를 넓히고 클럭을 높여 최고 성능에서는 경쟁력을 보였지만, 같은 시기 Arm 코어 대비 전력 효율이 떨어진다는 평가를 받았습니다. 자체 코어의 의미는 최고 점수가 아니라 **같은 전력에서의 성능**이며, 매년 Arm 코어가 빠르게 개선되는 상황에서 이 격차를 유지하지 못하면 자체 코어를 유지할 이유가 사라집니다. 삼성은 2019년 자체 CPU 코어 개발 조직을 정리했고, 이후 Exynos는 Arm 코어를 씁니다.

    **Oryon 클러스터 구조.** 스마트폰용 Oryon은 Arm 코어 기반 칩의 "코어 전용 L2 + DSU 공유 L3" 구조 대신, **클러스터가 큰 L2를 공유**하는 구조로 발표되었습니다. 또한 Snapdragon 8 Elite 세대는 고효율 코어 없이 `2 + 6`(최고 성능 2 + 성능 6) 구성으로 나왔습니다. 고효율 코어를 없앤 대신 성능 코어를 낮은 클럭·전압으로 깊게 내려 쓰는 방식이며, 이 구성이 대기 전력에 주는 영향은 실측 비교가 필요한 주제입니다([이기종 클러스터](clusters.md)).

    **자체 코어를 평가하는 방법.** 공개 정보가 적으므로 분석은 ① SPEC CPU 같은 표준 워크로드의 성능과 같은 시점의 전력 측정(성능/W 곡선), ② 마이크로벤치마크로 측정한 캐시 용량·지연, 분기 예측기 크기, 재정렬 버퍼 크기 추정, ③ 다이 사진에서 코어·캐시 면적 측정으로 이루어집니다. 이 책은 이런 수치를 쓸 때 **"공개 분석 기준, 추정"**으로 표시합니다([코어 마이크로아키텍처](microarchitecture.md)).

    **라이선스 구조의 영향.** 아키텍처 라이선스로 만든 자체 코어도 Arm에 로열티를 내지만, 코어 라이선스와 계약 구조가 다릅니다. Qualcomm의 Nuvia 인수 이후 Arm과 Qualcomm 사이에서 라이선스 적용 범위를 둘러싼 법적 분쟁이 있었던 것처럼, 자체 코어 전략은 기술뿐 아니라 계약 문제와 함께 움직입니다.

## 칩셋 비교

| 항목 | Apple | Snapdragon (Oryon) | Exynos·Dimensity (Arm 코어) |
|---|---|---|---|
| CPU 설계 | 자체 | 자체 | Arm |
| 클러스터 L2 | 공유 대형 L2 | 공유 대형 L2 | 코어 전용 L2 + 공유 L3 |
| 고효율 코어 | 있음 (자체 효율 코어) | 세대에 따라 없음 | 있음 (개수 감소 추세) |
| 같은 코어를 쓰는 다른 제품 | Mac·iPad | Windows PC | 같은 세대의 다른 회사 SoC |
