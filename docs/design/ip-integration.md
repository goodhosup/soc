# IP와 통합

!!! spec "규격 · 세대"
    IP 메타데이터: **IP-XACT**(IEEE 1685, 2009 → 2014 → 2022 개정) · 레지스터 기술: SystemRDL(Accellera) · 온칩 버스: Arm **AMBA**(APB·AHB·AXI·ACE·CHI) · 전원 의도: UPF(IEEE 1801) · 디버그: Arm CoreSight
    블록 단위 IP 라이선스(1990년대 Arm 코어) → 인터커넥트·PHY까지 사 오는 IP 생태계 → NoC 상용 IP 확산 → Arm이 코어·인터커넥트·물리 구현을 묶어 제공하는 **CSS**(Compute Subsystems, 2024년 무렵부터 발표)

!!! basic "한눈에 보기"
    SoC는 처음부터 끝까지 한 회사가 다 그리는 경우가 드뭅니다. 검증된 설계 블록을 사 와서(**IP 라이선스**) 직접 만든 블록과 함께 한 칩에 엮는 경우가 대부분입니다.

    1. **사 오는 IP** — CPU 코어, GPU, 인터커넥트, DRAM·USB·PCIe 같은 고속 인터페이스의 아날로그 회로(PHY)처럼 만들기 어렵고 검증이 많이 필요한 블록입니다.
    2. **직접 만드는 블록** — ISP, NPU, 모뎀처럼 회사의 차별점이 되는 블록입니다.
    3. **통합** — 모든 블록을 버스로 잇고, 클럭·리셋·전원을 나눠 주고, 소프트웨어가 블록을 제어할 레지스터 주소를 정합니다.

    레고에 비유하면, 표준 블록은 상자에서 꺼내 쓰고 특별한 모양은 직접 깎아 만든 뒤, 모두가 같은 규격의 돌기(버스 규격)로 맞물리도록 조립하는 일입니다.

## 누가 무엇을 공급하나 { .l2 }

| IP 종류 | 대표 공급사·제품 계열 | 비고 |
|---|---|---|
| CPU 코어·클러스터 | Arm Cortex·DSU, Arm CSS | 아키텍처 라이선스로 자체 코어를 만드는 회사도 있음([자체 설계 코어](../cpu/custom-cores.md)) |
| GPU | Arm Mali·Immortalis, Imagination PowerVR | Qualcomm Adreno·Apple GPU는 자체 설계, 삼성은 AMD RDNA 기반 GPU 라이선스 |
| 일관성 인터커넥트 | Arm CoreLink CCI·CMN, DSU 내부 | CPU 클러스터와 함께 구매하는 경우가 많음 |
| NoC | Arteris(FlexNoC·Ncore), Arm CoreLink NI 계열, 사내 설계 | 수십 개 블록을 잇는 패킷 기반 인터커넥트([버스와 인터커넥트](../basics/interconnect.md)) |
| 고속 인터페이스 PHY·컨트롤러 | Synopsys, Cadence, 파운드리 협력 IP 회사 | LPDDR, UFS(M-PHY), PCIe, USB, MIPI D-PHY·C-PHY |
| 기초 IP | 파운드리·IP 회사 제공 | 표준 셀 라이브러리, SRAM 컴파일러, I/O 셀, PLL |

**Arm CSS**는 코어·DSU·인터커넥트·시스템 IP를 미리 통합하고, 특정 파운드리 공정에서 물리 구현까지 마친 형태로 제공하는 상품입니다. 칩 회사는 통합·백엔드 일정을 줄이는 대신 차별화 여지를 일부 내려놓게 되며, 클라이언트용 CSS는 2025년 Lumex라는 이름으로 발표되었습니다(발표 기준).

## 통합 작업의 내용 { .l2 }

| 항목 | 하는 일 | 잘못되면 |
|---|---|---|
| 버스·주소 맵 | 각 IP의 AXI·CHI 포트를 인터커넥트에 연결하고 주소 영역 배정 | 접근 실패, 보안 영역 노출 |
| 클럭 | PLL에서 블록별 클럭을 나누고, 클럭 도메인 사이 신호에 동기화 회로 삽입 | CDC 버그 — 드물게, 재현하기 어렵게 오동작 |
| 리셋 | 리셋 순서와 도메인 정의, 리셋 해제 동기화 | 부팅 실패, 일부 블록만 이상 상태 |
| 전원 도메인 | UPF로 블록별 전원 차단·전압 영역 정의, 격리 셀·레벨 시프터 삽입 | 꺼진 블록의 신호가 켜진 블록을 오염 |
| 인터럽트·DMA | 인터럽트 번호, DMA 요청선, IOMMU 스트림 ID 배정 | 드라이버가 장치를 찾지 못함 |
| 레지스터 맵 | 블록별 제어 레지스터 정의 → RTL·헤더 파일·문서 자동 생성 | 하드웨어와 드라이버의 주소 불일치 |
| 디버그·추적 | CoreSight 추적·교차 트리거 연결 | 실리콘에서 문제 분석이 어려움 |

수십~수백 개 IP를 엮다 보면 연결 정보를 사람이 손으로 관리할 수 없습니다. **IP-XACT**는 IP의 포트·버스 인터페이스·레지스터·주소 공간을 XML로 기술하는 표준으로, 통합 도구가 이를 읽어 최상위 연결 RTL, 레지스터 헤더 파일, 검증 모델, 문서를 한꺼번에 생성합니다. 레지스터만 따로 기술할 때는 SystemRDL을 쓰는 경우도 많습니다.

??? expert "전문가 노트 — 라이선스 구조, IP 품질과 통합 리스크, 전원·클럭 통합의 함정"
    **라이선스 구조.** IP 거래는 보통 선불 라이선스 비용과 칩 출하량에 따른 로열티로 구성됩니다. Arm은 코어 IP를 그대로 쓰는 라이선스와 아키텍처만 쓰는 라이선스를 따로 운영하며, 로열티 산정 방식(칩 가격 기준 또는 기기 가격 기준)은 Arm과 칩 회사 사이의 분쟁 주제가 되기도 했습니다. 계약 조건은 공개되지 않으므로 비용 비중은 회사마다 다르다고만 말할 수 있습니다.

    **IP 품질과 통합 리스크.** 사 온 IP는 단독으로는 검증되어 있지만, 통합 환경의 클럭 비율·버스 폭·QoS 설정·전원 순서 조합에서 처음 드러나는 문제가 많습니다. 그래서 IP 공급사는 검증용 VIP(Verification IP)와 참조 통합 환경을 함께 제공하고, 칩 회사는 통합 단계에서 시스템 수준 테스트를 따로 만듭니다. PHY는 아날로그 회로라 공정·금속층 옵션마다 따로 실리콘으로 검증되어야 하므로, 원하는 공정에 검증된 PHY가 있는지가 파운드리 선택에 영향을 줍니다([파운드리와 공정](foundry.md)).

    **전원·클럭 통합의 함정.** 전원 도메인이 수십 개가 되면 "어떤 도메인이 꺼진 상태에서 어떤 신호가 살아 있는가"의 조합이 폭발합니다. UPF 기반 정적 검사와 전원 인식 시뮬레이션으로 격리 셀 누락, 레벨 시프터 방향 오류, 리텐션 레지스터 복원 순서를 확인합니다([파워 도메인과 게이팅](../power/power-domains.md)). CDC 역시 시뮬레이션으로는 잡기 어려워 구조적 검사 도구를 따로 씁니다.

    **레지스터 맵이 곧 소프트웨어 인터페이스.** 레지스터 맵을 바꾸면 드라이버·펌웨어·디바이스 트리가 모두 바뀌므로, 세대 간 같은 IP의 레지스터 호환성을 유지하는 것이 소프트웨어 재사용에 큰 영향을 줍니다. Linux 커널에 같은 드라이버가 여러 SoC의 compatible 문자열로 재사용되는 경우가 이런 사례입니다([Linux 커널과 SoC 지원](../software/linux-kernel.md)).
