# SoC란 무엇인가

!!! spec "규격 · 세대"
    SoC 자체를 정의하는 단일 표준은 없음 · 블록 사이 연결은 Arm AMBA(AXI·ACE·CHI), 외부 연결은 JEDEC LPDDR·UFS, MIPI CSI-2·DSI, PCIe, USB 같은 인터페이스 표준을 따름
    PC형 구조(CPU + 노스브리지 + 사우스브리지 + 그래픽 카드) → 피처폰 시절 베이스밴드 칩 + 별도 AP → 스마트폰 AP에 GPU·ISP 통합 → 모뎀까지 한 다이에 통합(통합 5G 모뎀 SoC는 2019년 무렵부터 상용화)

!!! basic "한눈에 보기"
    **SoC(System on Chip)**는 컴퓨터 한 대를 이루는 부품을 **실리콘 조각 하나**에 모은 칩입니다.

    데스크톱 PC를 열어 보면 CPU, 그래픽 카드, 메모리 컨트롤러가 들어 있는 메인보드 칩셋, 네트워크 카드가 따로 꽂혀 있습니다. 스마트폰에는 그럴 공간도, 배터리도 없습니다. 그래서 이 부품들을 손톱만 한 칩 한 개에 모아 넣었습니다.

    1. **작게** — 부품 사이를 잇는 보드 배선이 사라져 기판이 작아집니다.
    2. **적은 전력으로** — 칩 밖으로 신호를 내보내는 데 드는 전력이 칩 안에서 주고받는 것보다 훨씬 큽니다.
    3. **빠르게** — 블록끼리 가까이 있으니 데이터를 주고받는 지연이 짧습니다.
    4. **싸게** — 부품 수가 줄어 조립 비용이 줄어듭니다.

    대신 한 칩에 모든 것을 넣으니 설계가 어렵고, 한 블록만 바꾸고 싶어도 칩 전체를 다시 만들어야 합니다.

## SoC 안의 블록 { .l2 }

![스마트폰 SoC의 블록 구성](../assets/figures/basics_soc_blocks.svg)

| 블록 | 하는 일 | 이 책의 장 |
|---|---|---|
| CPU 클러스터 | 운영체제와 앱 실행. 성능이 다른 코어 여러 종류를 섞어 씀 | [CPU](../cpu/index.md) |
| GPU | 화면 그리기(3D·UI 합성)와 병렬 연산 | [GPU](../gpu/index.md) |
| NPU | 신경망 연산 전용 가속기 | [NPU와 AI](../npu/index.md) |
| DSP | 오디오·센서·통신 신호 처리, 저전력 상시 동작 작업 | [멀티미디어](../media/index.md) |
| ISP | 이미지 센서의 RAW 데이터를 사진·영상으로 바꿈 | [멀티미디어](../media/isp.md) |
| 비디오 코덱 | H.264·HEVC·AV1 인코딩·디코딩 | [멀티미디어](../media/video-codec.md) |
| 디스플레이 엔진 (DPU) | 여러 화면 레이어를 합성해 패널로 내보냄 | [멀티미디어](../media/display.md) |
| 모뎀 | LTE·5G 신호 처리 (일부 칩은 외장) | [연결](../connectivity/modem.md) |
| 인터커넥트·SLC | 블록 사이의 데이터 길과 공유 캐시 | [버스와 인터커넥트](../basics/interconnect.md) |
| 메모리 컨트롤러 | 외부 LPDDR DRAM 읽기·쓰기 | [메모리와 저장장치](../memory/index.md) |
| 보안 블록 | 보안 부팅, 키 저장, 암호 가속 | [보안과 부팅](../security/index.md) |
| 전력 관리 MCU | 전압·클럭 조절, 저전력 상태 관리 | [전력과 열](../power/index.md) |
| 입출력 (I/O) | UFS, PCIe, USB, 카메라·디스플레이 MIPI, I2C·SPI 등 | [연결](../connectivity/index.md) |

SoC 밖에 남는 대표적인 칩은 **DRAM**(보통 SoC 위에 쌓음), **UFS 저장장치**, **PMIC**(전원 칩), **RF 프런트엔드**(안테나 쪽 증폭기·필터), 그리고 칩에 따라 **Wi-Fi·Bluetooth 콤보 칩**입니다.

## 왜 한 칩에 모으나 { .l2 }

| 관점 | 따로 만들 때 | 한 칩에 모을 때 |
|---|---|---|
| 신호 전력 | 칩 밖으로 나가는 신호는 패드·보드 배선의 큰 정전 용량을 구동해야 함 | 칩 안 배선은 정전 용량이 작아 같은 데이터를 훨씬 적은 에너지로 옮김 |
| 지연 | 칩 사이 인터페이스를 거치며 수십~수백 ns 추가 | 인터커넥트 안에서 수 ns 단위 |
| 대역폭 | 핀 수가 제한되어 넓은 버스를 만들기 어려움 | 수백~수천 비트 폭의 내부 버스 가능 |
| 메모리 공유 | 각 칩이 자기 메모리를 따로 가짐 → 데이터 복사 | CPU·GPU·NPU가 같은 DRAM을 공유 (복사 없이 넘김) |
| 크기·비용 | 부품·기판 면적·조립 비용 증가 | 부품 수 감소 |
| 유연성 | 블록별로 따로 교체·업그레이드 가능 | 한 블록을 바꿔도 칩 전체를 다시 설계·생산 |
| 설계 위험 | 칩마다 위험이 나뉨 | 한 블록의 버그가 칩 전체를 망칠 수 있음 |

모바일에서는 전력과 크기가 절대적이므로 통합의 이점이 압도적입니다. 반면 PC·서버는 공간과 전력 여유가 있어서 오랫동안 분리 구조를 유지했고, 최근에야 Apple M 시리즈나 Snapdragon X 같은 통합형 칩이 노트북으로 넘어오고 있습니다([Arm PC와 노트북 SoC](../next/arm-pc.md)).

??? expert "전문가 노트 — 통합의 한계와 칩렛, 공유 메모리의 비용"
    **무엇을 통합하지 않나.** 모든 블록이 같은 공정에서 이득을 보지는 않습니다. 로직(CPU·GPU)은 최신 공정일수록 밀도와 전력이 좋아지지만, 아날로그·RF·고전압 회로는 미세 공정의 이득이 작거나 오히려 불리합니다. 그래서 RF 송수신기, PMIC, 전력 증폭기는 별도 칩으로 남고, DRAM은 전혀 다른 공정(커패시터 기반 메모리 공정)이라 SoC와 같은 다이에 넣을 수 없습니다. 모뎀도 세대에 따라 통합(전력·면적 유리)과 외장(개발 일정 분리, 지역별 사양 대응)을 오갑니다.

    **다이 면적의 한계.** 다이가 커지면 웨이퍼당 개수가 줄고 결함 하나가 칩 하나를 버리게 만드는 확률이 커집니다(→ [성능·전력·면적 (PPA)](../basics/ppa.md)의 수율 계산). 스마트폰 SoC 다이는 대략 100 mm² 안팎에서 설계되는 경우가 많아, 이 예산 안에서 CPU·GPU·NPU·캐시가 면적을 다툽니다. 서버·PC 칩은 이 한계를 넘기 위해 여러 다이를 한 패키지에 묶는 **칩렛** 방식으로 가고 있으며, 모바일에서도 패키지 수준 통합이 논의됩니다([패키징](../design/packaging.md)).

    **통합 메모리의 비용.** CPU·GPU·NPU·ISP·디스플레이가 같은 DRAM을 공유하면 데이터 복사는 줄지만, 대역폭을 서로 다툽니다. 카메라 촬영 중 게임을 돌리면 ISP와 GPU가 같은 메모리 대역폭을 나눠 쓰고, 디스플레이 엔진은 화면이 끊기지 않도록 최우선으로 대역폭을 보장받아야 합니다. 그래서 메모리 컨트롤러와 인터커넥트의 **QoS(서비스 품질) 우선순위** 설계가 SoC 성능을 크게 좌우합니다([메모리 컨트롤러와 SLC](../memory/controller-slc.md)).

    **"같은 칩"의 변형.** 같은 SoC라도 제조사는 클럭을 높인 특별판, 일부 코어나 GPU 블록을 끈 하위 판을 내놓습니다. 시험에서 모든 블록이 통과하지 못한 다이를 일부 기능을 끄고 파는 방식(빈닝)이 섞여 있어, 이름이 비슷한 칩이라도 사양을 꼭 확인해야 합니다([시험과 양산](../design/test.md)).

## SoC ↔ PC형 구조 비교

| 항목 | 스마트폰 SoC | 전통적인 PC |
|---|---|---|
| CPU·GPU | 한 다이, 같은 DRAM 공유 | CPU와 독립 GPU(전용 VRAM) 분리 |
| 메모리 | LPDDR, SoC 패키지 위에 적층하거나 바로 옆에 배치 | DIMM 슬롯의 DDR, 교체 가능 |
| 저장장치 | UFS (보드에 납땜) | SATA·NVMe SSD (교체 가능) |
| 전력 예산 | 지속 수 W, 순간 10 W 안팎 | 수십~수백 W |
| 확장성 | 없음 (칩 교체 불가) | 카드·메모리·저장장치 교체 |
