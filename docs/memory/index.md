# 메모리와 저장장치

이 섹션은 SoC 바깥, 그러나 SoC 성능을 직접 좌우하는 **DRAM과 저장장치**, 그리고 그 앞을 지키는 **메모리 컨트롤러·SLC·IOMMU**를 다룹니다. CPU·GPU·NPU가 아무리 빨라도 데이터가 제때 오지 않으면 기다릴 뿐이며, 온디바이스 AI 시대에는 **메모리 대역폭이 곧 성능**인 경우가 많아졌습니다.

|---|---|
| [LPDDR](lpddr.md) | LPDDR4X → 5 → 5X → 6에서 무엇이 바뀌었고, 대역폭은 어떻게 계산하나? |
| [메모리 컨트롤러와 SLC](controller-slc.md) | 여러 블록의 요청을 어떻게 줄 세우고, 시스템 레벨 캐시는 무엇을 아끼나? |
| [패키지와 PoP](packaging.md) | DRAM을 SoC 위에 쌓는 이유와 그 대가는? |
| [UFS 저장장치](ufs.md) | UFS 3.1 → 4.0 → 4.1에서 무엇이 빨라졌고, 순차·랜덤 성능은 왜 다른가? |

!!! basic "대역폭 계산 미리 보기"
    DRAM 피크 대역폭은 간단한 곱셈입니다.

    **대역폭 = 핀당 데이터 레이트 × 버스 폭 ÷ 8**

    스마트폰은 보통 16비트 채널 4개, 합쳐 **64비트** 버스를 씁니다. 예를 들어 LPDDR5X-8533(핀당 8533 MT/s)이면 8533 × 64 ÷ 8 ≈ **68.3 GB/s**입니다. 사양표의 "LPDDR5X 10.7 Gbps"는 핀당 속도이므로, 같은 계산으로 약 **85.3 GB/s**가 됩니다. (수치는 `tools/soc_numbers.py`에서 계산)

!!! tip "다른 섹션과의 연결"
    캐시와 DRAM의 속도 차이는 [메모리 계층](../basics/memory-hierarchy.md), DRAM 대역폭이 온디바이스 LLM 속도를 정하는 원리는 [온디바이스 LLM](../npu/llm.md), 장치 격리의 보안 측면은 [TrustZone과 TEE](../security/trustzone.md)에서 다룹니다.
