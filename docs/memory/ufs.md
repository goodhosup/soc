# UFS 저장장치

!!! spec "규격 · 세대"
    JEDEC UFS(JESD220 계열) + MIPI M-PHY(물리 계층) + MIPI UniPro(링크 계층) · UFS 2.x(HS-G3) → **UFS 3.0**(HS-G4, 2018) → **UFS 3.1**(WriteBooster 등, 2020) → **UFS 4.0**(HS-G5, M-PHY 5.0·UniPro 2.0, 2022) → UFS 4.1(기능 개선) → UFS 5.0(개발 발표 단계)
    스마트폰 적용: eMMC → UFS 2.x(2010년대 중반 플래그십) → UFS 3.x → UFS 4.x(2023년형 플래그십부터 주류)

!!! basic "한눈에 보기"
    **UFS(Universal Flash Storage)**는 스마트폰의 저장장치입니다. 앱, 사진, 운영체제가 모두 여기에 저장됩니다. PC의 SSD와 같은 낸드 플래시를 쓰지만, 모바일에 맞게 작은 패키지와 저전력 인터페이스를 씁니다.

    1. **전이중 고속 직렬 링크** — 읽기와 쓰기 선을 따로 두고 동시에 주고받습니다. 이전 세대 eMMC는 한 길을 번갈아 썼습니다.
    2. **명령 큐** — 여러 요청을 한꺼번에 받아 순서를 바꿔 처리할 수 있어, 앱이 여러 파일을 동시에 읽을 때 빠릅니다.
    3. **두 가지 속도** — 큰 파일을 이어서 읽는 **순차 속도**와 작은 조각을 여기저기 읽는 **랜덤 속도**가 크게 다릅니다. 앱 실행 체감은 랜덤 속도에 더 좌우됩니다.

## 세대별 비교 { .l2 }

| 항목 | UFS 2.1 | UFS 3.1 | UFS 4.0 / 4.1 |
|---|---|---|---|
| M-PHY 기어 | HS-G3 | HS-G4 | HS-G5 |
| 레인당 속도 (Rate B) | 약 5.8 Gbps | 약 11.7 Gbps | 약 23.3 Gbps |
| 2레인 원시 링크 속도 | 약 11.7 Gbps | 약 23.3 Gbps | 약 46.6 Gbps |
| 대표 순차 읽기 (제조사 발표) | 1 GB/s 안팎 | 2 GB/s 안팎 | 4 GB/s대 |
| 주요 기능 | 명령 큐 | WriteBooster(SLC 버퍼), DeepSleep | 더 높은 속도, 전력 효율 개선, 4.1에서 기능 추가 |

원시 링크 속도는 선로 부호화·프로토콜 오버헤드 전의 값이며, 실제 순차 속도는 이보다 낮습니다. 표의 순차 속도는 제조사 발표의 대표 범위입니다. (링크 속도는 `tools/soc_numbers.py`에서 계산)

## 계층 구조 { .l2 }

| 계층 | 담당 | 내용 |
|---|---|---|
| 응용 계층 | UFS 명령 세트 (SCSI 기반) | 읽기·쓰기·관리 명령, 논리 유닛(LU) |
| 전송 계층 | UTP | 명령·데이터·응답을 UPIU 패킷으로 |
| 링크 계층 | MIPI UniPro | 신뢰성 있는 전송, 흐름 제어 |
| 물리 계층 | MIPI M-PHY | 고속 직렬 차동 신호, 기어·레인 |

SoC 쪽에는 **UFS 호스트 컨트롤러**(UFSHCI 표준 레지스터 인터페이스)와 M-PHY가 있고, 저장장치 쪽에는 컨트롤러와 낸드 플래시가 한 패키지에 들어 있습니다. 저장 데이터 암호화는 보통 SoC의 **인라인 암호 엔진**이 UFS 경로 위에서 처리합니다([암호 가속과 키 관리](../security/crypto.md)).

??? expert "전문가 노트 — 순차 속도의 함정, WriteBooster, 장기 성능 저하"
    **순차 속도의 함정.** 앱 실행·설치·사진 썸네일 로딩은 4 KB 단위 랜덤 읽기와 짧은 큐 깊이가 지배하는 경우가 많습니다. 이 영역의 성능은 링크 속도보다 **낸드 읽기 지연과 저장장치 컨트롤러의 매핑 테이블 관리**에 좌우되므로, UFS 세대가 오를 때 순차 속도만큼 체감이 늘지는 않습니다. 저장장치 비교는 순차·랜덤·큐 깊이별 결과를 나눠 봐야 합니다.

    **WriteBooster.** TLC·QLC 낸드는 셀당 여러 비트를 저장해 쓰기가 느리므로, 일부 영역을 셀당 1비트(SLC 모드)로 써서 빠르게 받아 두고 나중에 옮깁니다. 버퍼가 차거나 저장 공간이 거의 찼을 때는 이 이득이 줄어, 대용량 연속 촬영·파일 복사 중 쓰기 속도가 갑자기 떨어질 수 있습니다.

    **장기 성능 저하와 관리 명령.** 낸드는 덮어쓰기가 안 되고 블록 단위로 지워야 하므로, 저장장치 내부의 가비지 컬렉션과 웨어 레벨링이 필요합니다. 운영체제의 discard(삭제 알림)와 유휴 시간 관리가 이를 돕습니다. 저장 공간이 꽉 찬 상태가 오래 지속되면 내부 정리 여지가 줄어 성능이 떨어질 수 있습니다.

    **커널에서 보이는 모습.** Linux의 UFS 드라이버는 `drivers/ufs/`에 공통 코어와 SoC별 확장이 있고, 기어·레인 상태와 전력 모드는 `/sys/bus/platform/drivers/ufshcd/*/` 아래 속성으로 확인할 수 있습니다(경로는 플랫폼마다 다름). 저장장치는 부하가 낮으면 기어를 낮추거나 링크를 절전 상태로 두어 전력을 아낍니다.

## UFS ↔ eMMC ↔ NVMe 비교

| 항목 | eMMC | UFS | NVMe (PC·일부 기기) |
|---|---|---|---|
| 링크 | 병렬 버스, 반이중 | 직렬, 전이중 | PCIe 직렬 |
| 명령 큐 | 제한적 | 있음 | 다중 큐, 깊은 큐 |
| 전력 | 낮음 | 낮음 (모바일 최적화) | 상대적으로 높음 |
| 사용처 | 보급형·임베디드 | 스마트폰 주류 | PC, 일부 태블릿·노트북 |
