# RISC-V의 부상

!!! spec "규격 · 세대"
    RISC-V International 비준 규격: 비특권 ISA(RV32I·RV64I 기본 + M·A·F·D·C 확장, 2019 비준) · 특권 ISA · **벡터 확장 V 1.0**(2021) · 하이퍼바이저 확장 H(2021)
    프로파일: RVA20 → RVA22 → **RVA23**(2024년 비준, 응용 프로세서용 — V·H 필수)
    시작: UC Berkeley 연구 프로젝트(2010) → RISC-V Foundation(2015) → RISC-V International(2020, 스위스)
    스마트폰 SoC 앱 프로세서로 RISC-V를 쓴 상용 플래그십은 없음(이 페이지 기준 시점) · SoC 내부 마이크로컨트롤러로는 이미 널리 사용

!!! basic "한눈에 보기"
    **ISA(명령어 집합 구조)**는 CPU와 소프트웨어 사이의 "언어"입니다. Arm ISA를 쓰려면 Arm과 라이선스 계약을 맺어야 하지만, **RISC-V는 누구나 무료로 쓸 수 있는 공개 ISA**입니다.

    1. **공개 규격** — 언어의 문법책이 공개되어 있어, 누구나 그 언어를 말하는 CPU를 만들 수 있습니다.
    2. **작은 기본 + 확장** — 꼭 필요한 기본 명령어는 아주 작고, 곱셈·부동소수점·벡터 같은 기능은 필요한 것만 골라 붙입니다.
    3. **이미 폰 안에 있음** — 앱을 돌리는 큰 CPU는 아직 Arm이지만, 전원 관리·카메라·모뎀 같은 블록을 조용히 관리하는 작은 CPU에는 RISC-V가 많이 쓰입니다.
    4. **남은 과제** — 큰 CPU로 쓰려면 성능 좋은 코어, Android 같은 운영체제와 앱 생태계가 모두 준비되어야 합니다.

    비유하면 Arm은 잘 정비된 유료 고속도로, RISC-V는 누구나 길을 낼 수 있는 공유지입니다. 자유롭지만, 모두가 같은 규격으로 길을 내야 서로 이어집니다.

## ISA 구조와 프로파일 { .l2 }

| 구성 | 내용 | 비고 |
|---|---|---|
| 기본 정수 ISA | RV32I, RV64I (32비트·64비트) | 수십 개 명령어의 작은 핵심 |
| M · A · F · D | 곱셈·나눗셈, 원자적 연산, 단·배정밀도 부동소수점 | 묶어서 "G"(범용)라고 부름 |
| C | 16비트 압축 명령어 | 코드 크기 감소, 마이크로컨트롤러에 중요 |
| V | 벡터 확장, 벡터 길이를 구현마다 다르게 정할 수 있음(VLA) | Arm SVE와 비슷한 철학 |
| H | 하이퍼바이저 지원 | 가상화, Android의 보호 VM 같은 기능에 필요 |
| 사용자 정의 확장 | 회사마다 고유 명령어 추가 가능 | 장점이자 파편화의 원인 |
| **프로파일** | 응용 프로세서가 반드시 갖춰야 할 확장 묶음 (RVA22, RVA23 등) | OS·앱이 기대할 수 있는 공통 기준 |

RISC-V가 응용 프로세서 시장에서 오래 겪은 문제는 "어떤 확장을 갖춘 칩인지 제각각"이라는 점이었습니다. **RVA23** 프로파일은 벡터(V)와 하이퍼바이저(H)를 필수로 넣어, Android나 일반 Linux 배포판이 하나의 바이너리 기준으로 삼을 수 있는 목표를 제시했습니다. Arm으로 치면 "Armv9-A를 지원하는 코어"라고 말할 수 있게 된 것과 비슷합니다([Arm 아키텍처](../cpu/arm-architecture.md)).

## 스마트폰 SoC 안의 RISC-V { .l2 }

| 위치 | 하는 일 | 왜 RISC-V인가 |
|---|---|---|
| 전력·시스템 관리 마이크로컨트롤러 | 전원 시퀀스, DVFS 요청 처리, 부팅 초기 단계 | 라이선스 비용 없이 작은 코어를 여러 개 배치 |
| 모뎀·연결 칩 내부 제어 | 프로토콜 보조, 펌웨어 실행 | 필요한 명령어만 맞춤 추가 |
| 카메라·센서·오디오 보조 | 제어 루프, 저전력 상시 동작 | 작은 면적과 낮은 전력 |
| GPU·가속기 내부 관리 코어 | 작업 스케줄링, 펌웨어 | 기존 자체 마이크로컨트롤러를 대체 |

이런 코어는 사용자에게 보이지 않고 회사 내부 펌웨어만 돌리므로, 앱 생태계가 필요 없습니다. Qualcomm은 자사 제품에 RISC-V 마이크로컨트롤러를 넣어 왔다고 밝혔고, NVIDIA도 GPU 내부 제어 코어를 RISC-V로 바꿨다고 발표했습니다. RISC-V가 **"보이지 않는 곳부터"** 퍼진 이유입니다([센서 허브](../media/sensor-hub.md)).

### 앱 프로세서로 가는 길 (발표·보도 기준)

| 영역 | 상황 |
|---|---|
| Android | Google이 RISC-V를 Android 지원 아키텍처로 추가하는 작업을 진행, 2024년 Android 공용 커널(ACK)에서 riscv64 지원이 제거되어 GKI 빌드에서 빠짐(Google은 RISC-V 지원을 계속한다고 밝힘). 이 페이지 기준 시점에도 GKI 기반 RISC-V 상용 Android 기기는 없음. 정식 지원 수준은 AOSP 공지로 확인 필요 |
| 업계 협력 | RISE 프로젝트(2023, Linux Foundation Europe) — 여러 칩·소프트웨어 회사가 RISC-V용 툴체인·런타임을 함께 준비 |
| Qualcomm | Google과 RISC-V 기반 Wear OS 플랫폼 협력 발표(2023), 차량용 RISC-V 합작사 Quintauris 참여, 서버급 RISC-V CPU 설계사 Ventana Micro Systems 인수 발표(2025년 12월) |
| SiFive | RISC-V 코어 IP 회사. 고성능 P 계열, 벡터·AI용 X·Intelligence 계열 |
| T-Head (Alibaba) | XuanTie C9xx 계열 고성능 코어, 중국 내 RISC-V 생태계의 주요 축 |
| 기타 | Andes(코어 IP), Tenstorrent(고성능 코어 IP) 등 |

??? expert "전문가 노트 — 확장 파편화와 프로파일, 벡터 길이와 앱 호환, 앱 프로세서 전환의 진짜 비용"
    **파편화를 막는 장치.** RISC-V는 사용자 정의 확장을 허용하는 것이 강점이지만, 응용 프로세서에서는 바이너리 호환이 깨지는 원인이 됩니다. 그래서 OS와 컴파일러는 프로파일(RVA23 등)을 기준선으로 삼고, 그 밖의 확장은 런타임에 감지해서 쓰는 방식(Linux의 hwprobe 같은 인터페이스)으로 정리되고 있습니다. 회사 고유 확장은 펌웨어나 전용 라이브러리 안에 가두는 것이 일반적인 해법입니다.

    **벡터 길이 독립 코드.** V 확장은 하드웨어 벡터 레지스터 길이(VLEN)가 구현마다 다를 수 있고, 코드는 실행 시점에 길이를 물어보며 루프를 돕니다. Arm SVE와 같은 방식이라 한 바이너리가 여러 칩에서 돌 수 있지만, NEON처럼 고정 128비트를 가정하고 최적화된 기존 Android 네이티브 라이브러리(코덱, 이미지 처리, ML 커널)는 다시 작성해야 성능이 나옵니다. 또 V 1.0 이전 초안(0.7.1)을 구현한 초기 칩이 있어, 같은 "벡터 지원"이라도 호환되지 않는 경우가 있었습니다.

    **앱 프로세서 전환의 비용.** 스마트폰 플래그십 CPU는 ISA보다 마이크로아키텍처 경쟁입니다. 넓은 디코드·큰 ROB·정교한 분기 예측기를 갖춘 RISC-V 코어가 공개되고 있지만, Arm 최상위 코어와 비슷한 성능·전력을 양산 SoC에서 보여 준 사례는 이 페이지 기준 시점에 드뭅니다. 게다가 Android 앱의 상당수는 Arm용 네이티브 코드(NDK)를 포함하므로, 전환하려면 앱 재빌드나 바이너리 번역이 필요합니다. 그래서 RISC-V는 웨어러블·IoT·차량용·데이터센터 가속기처럼 **소프트웨어 스택을 한 회사가 통제할 수 있는 영역**에서 먼저 앱 프로세서로 쓰이는 흐름입니다([Arm PC와 노트북 SoC](arm-pc.md)에서 본 Arm의 x86 전환과 같은 문제입니다).

    **보안·부팅 생태계.** 스마트폰 SoC는 TrustZone, TF-A, PSCI, SMMU 같은 Arm 생태계의 표준 부품 위에 서 있습니다. RISC-V에도 대응하는 규격(SBI, 물리 메모리 보호 PMP, IOMMU 규격, 신뢰 실행 환경 제안들)이 있지만, 성숙도와 검증된 구현의 수가 아직 적습니다([TrustZone과 TEE](../security/trustzone.md)).

## 칩셋 비교

| 접근 | Arm (현재 스마트폰 표준) | RISC-V |
|---|---|---|
| 라이선스 | Arm과 계약 (코어 IP 또는 아키텍처 라이선스) | ISA 무료, 코어 IP는 SiFive 등에서 구매하거나 자체 설계 |
| 확장 | Arm이 정의, 회사별 고유 명령어는 원칙적으로 불가 (일부 Cortex-M의 Arm Custom Instructions는 예외) | 사용자 정의 확장 허용 |
| 호환성 기준 | 아키텍처 버전(Armv8·v9) | 프로파일(RVA22·RVA23) |
| 스마트폰 SoC 내 위치 | 앱 CPU, 다수 마이크로컨트롤러 | 마이크로컨트롤러·관리 코어 중심 |
| 소프트웨어 생태계 | Android·iOS 완비 | Linux 성숙, Android는 지원 작업 진행 중 |

> 세대별 칩셋의 CPU 구성은 [칩셋 세대 인덱스](../reference/chipset-index.md)에 모읍니다.
