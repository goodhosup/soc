# TOPS와 정밀도

!!! spec "규격 · 세대"
    수 형식: IEEE 754 **FP32·FP16**, **BF16**(bfloat16), **FP8**(E4M3·E5M2, OCP 8-bit Floating Point 사양) · OCP **Microscaling(MX)** 형식(MXFP8·MXFP4 등, 2023) · 정수 **INT8·INT4**(대칭·비대칭 양자화, 채널·그룹별 스케일)
    모바일 NPU의 흐름: INT8 중심(2018–2019년형) → FP16 병행 지원 → INT4 지원과 생성형 AI 대응(2023년형 무렵부터) → 일부 최신 세대의 FP8·저비트 부동소수점 지원(이 페이지 기준 시점, 회사별 발표 확인 필요)

!!! basic "한눈에 보기"
    **TOPS(Tera Operations Per Second)**는 "1초에 연산을 몇 조 번 할 수 있나"를 뜻하는 숫자입니다. 자동차의 최고 속도처럼, **이론상 낼 수 있는 최댓값**입니다.

    1. 숫자를 **짧게 쓸수록**(8비트 → 4비트) 같은 회로에서 더 많이 계산할 수 있어 TOPS가 커집니다.
    2. **0을 건너뛰는 계산(희소성)**을 포함하면 숫자가 또 커집니다.
    3. 하지만 실제 앱에서는 데이터를 기다리거나 지원되지 않는 연산 때문에 최댓값의 일부만 씁니다.

    최고 속도 300 km/h인 차도 시내에서는 신호와 정체 때문에 평균 30 km/h로 달리는 것과 같습니다. TOPS는 **어떤 정밀도에서, 어떤 조건으로 센 숫자인지**를 함께 봐야 의미가 있습니다.

## TOPS 계산 { .l2 }

$$
\text{TOPS} = \frac{N_{MAC} \times 2 \times f_{clk}}{10^{12}}
$$

MAC 한 번은 곱셈과 덧셈 두 연산으로 셉니다. 예를 들어 MAC 4096개, 1 GHz라면 다음과 같습니다(가상의 예). (수치는 `tools/soc_numbers.py`에서 계산)

| 표기 조건 | 계산 | 결과 |
|---|---|---|
| INT8 밀집(dense) | 4096 × 2 × 1 GHz | 약 **8.2 TOPS** |
| INT4 밀집 (INT8 MAC 하나가 INT4 둘을 처리한다고 가정) | 8.2 × 2 | 약 **16.4 TOPS** |
| INT4 + 2배 희소성 가정 | 16.4 × 2 | 약 **32.8 TOPS** |
| 실제 모델에서 이용률 40% 가정 (INT8) | 8.2 × 0.4 | 약 **3.3 TOPS** 유효 |

같은 하드웨어가 표기 방식에 따라 **3.3에서 32.8까지 열 배 가까이** 다르게 보일 수 있습니다. FP16 성능은 구현에 따라 INT8의 절반 이하인 경우가 많으며, 별도로 TFLOPS로 표기하기도 합니다.

## 정밀도별 특징 { .l2 }

| 형식 | 비트 | 주된 용도 | 주의할 점 |
|---|---|---|---|
| FP32 | 32 | 학습, 기준 정확도 | 모바일 NPU에서는 거의 쓰지 않음 (CPU·GPU 몫) |
| FP16 / BF16 | 16 | 정확도에 민감한 모델, 이미지 생성, 활성화 | INT8 대비 메모리·전력 2배 |
| FP8 (E4M3·E5M2) | 8 | 부동소수점의 넓은 범위를 8비트로 | 모바일 NPU 지원은 세대·회사별로 다름 |
| INT8 | 8 | 비전·음성 모델 추론의 표준 | 양자화 보정(calibration)이나 양자화 인식 학습이 필요 |
| INT4 | 4 | LLM 가중치 저장 (가중치만 INT4, 활성화는 INT8·FP16) | 그룹별 스케일 없이는 정확도 손실이 큼 |

양자화된 값은 정수 $q$와 스케일 $s$(필요하면 영점 $z$)로 실수를 근사합니다: $x \approx s \cdot (q - z)$. 스케일을 텐서 전체에 하나 두면 단순하지만 정확도가 떨어지고, 채널·그룹(예: 32·128개 단위)마다 두면 정확도는 좋아지지만 스케일 저장과 처리 비용이 늘어납니다.

## TOPS가 오해를 부르는 이유 { .l2 }

| 함정 | 설명 |
|---|---|
| 정밀도 혼합 | 한 회사는 INT8, 다른 회사는 INT4나 희소성 포함 숫자를 발표할 수 있음 |
| "AI 엔진 전체" 합산 | NPU에 CPU·GPU의 연산량까지 더한 플랫폼 합계를 발표하는 경우가 있음 |
| 메모리 한계 | 데이터가 늦게 오면 MAC이 놀아 피크에 한참 못 미침 (특히 LLM 생성 단계) |
| 지원 연산 | 지원하지 않는 연산이 CPU로 넘어가면 그 구간은 NPU TOPS와 무관 |
| 지속 성능 | 피크 클럭은 발열 때문에 오래 유지되지 않을 수 있음 |

??? expert "전문가 노트 — 이용률, 희소성의 조건, TOPS/W의 측정 조건"
    **이용률(utilization).** 유효 성능은 피크 TOPS × 이용률이며, 이용률은 ① 텐서 형상이 MAC 배열 크기에 딱 맞는지(채널 수가 배열 폭의 배수가 아니면 일부 MAC이 빈다), ② 로컬 SRAM에 타일이 들어가는지, ③ DMA가 연산과 겹쳐 돌아가는지, ④ 벡터 연산(소프트맥스·정규화)이 텐서 엔진을 기다리게 하는지에 좌우됩니다. 깊이별 합성곱(depthwise)이나 작은 배치의 행렬-벡터 곱은 구조적으로 이용률이 낮습니다. 위 표의 40%는 설명을 위한 가정이며 실제 값은 모델·컴파일러에 따라 크게 달라집니다.

    **희소성 숫자의 조건.** 희소성 가속은 가중치 중 0을 건너뛰어 연산을 줄이는 기법입니다. 하드웨어가 가속할 수 있는 것은 보통 일정한 패턴(예: 연속한 4개 중 2개가 0인 2:4 구조적 희소성)이며, 모델을 그 패턴에 맞게 가지치기하고 재학습해야 정확도가 유지됩니다. 일반적인 사전 학습 모델을 그대로 돌리면 희소성 배수는 적용되지 않으므로, "희소성 포함" TOPS는 밀집 TOPS와 따로 읽어야 합니다.

    **TOPS/W의 측정 조건.** 전력당 성능은 NPU의 진짜 경쟁력이지만, 어떤 전압·클럭 점에서 쟀는지, NPU 코어만인지 SRAM·DRAM 전력까지 포함인지에 따라 몇 배씩 달라집니다. 예를 들어 위 가상 NPU가 8.2 TOPS에서 2 W를 쓴다면 약 4.1 TOPS/W지만, DVFS로 클럭과 전압을 낮춘 점에서는 TOPS/W가 더 높게 나옵니다([DVFS와 전력 관리](../power/dvfs.md)). 같은 이유로 회사 간 TOPS/W 비교는 측정 조건이 공개되지 않으면 의미가 약합니다. (수치는 `tools/soc_numbers.py`에서 계산)

    **정밀도와 누적기.** INT8 곱의 누적은 INT32에서, FP16·FP8 곱의 누적은 FP16보다 넓은 형식(FP32 등)에서 하는 경우가 많습니다. 누적 폭이 좁으면 긴 내적에서 오차가 쌓이므로, 저정밀 TOPS가 높더라도 누적·재양자화 경로가 정확도를 결정합니다. 실무에서는 정확도 지표(예: 분류 정확도, LLM의 perplexity)를 정밀도별로 함께 비교해야 합니다.
