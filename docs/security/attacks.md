# 하드웨어 공격과 대응

!!! spec "규격 · 세대"
    Arm 완화 기능: **PAC**(Pointer Authentication, Armv8.3) · **BTI**(Branch Target Identification, Armv8.5) · **MTE**(Memory Tagging Extension, Armv8.5) · 투기 실행 완화(CSV2·CSV3, `SB`·`CSDB` 명령, SSBS) · **CCA**(Confidential Compute Architecture, Armv9.2 RME) · CoreSight 인증 디버그 · JEDEC LPDDR5 RFM(Refresh Management)
    공개 연구의 흐름: 전력 부채널(1990년대 말) → 캐시 타이밍 → Rowhammer(2014)와 모바일 Rowhammer(2016) → Spectre·Meltdown(2018) → 포인터 인증·메모리 태그를 노리는 투기 실행 연구(2022년 이후)

!!! basic "한눈에 보기"
    소프트웨어 버그가 없어도 하드웨어의 **물리적 성질**을 이용해 비밀을 빼내거나 검사를 건너뛸 수 있습니다.

    1. **결함 주입** — 전압·클럭을 순간적으로 흔들어 칩이 계산을 틀리게 만듭니다. "서명 검사 실패" 분기를 건너뛰게 하는 것이 대표적입니다.
    2. **부채널** — 전력 소모, 전자파, 실행 시간처럼 밖으로 새는 신호에서 비밀을 추측합니다.
    3. **마이크로아키텍처 공격** — 캐시·분기 예측기·DRAM의 동작을 일부러 이용해 다른 프로그램의 데이터를 엿봅니다.

    금고 비밀번호를 몰라도 다이얼을 돌릴 때 나는 소리(부채널)로 맞히거나, 금고를 세게 쳐서 잠금장치를 튕겨 내는(결함 주입) 것과 비슷합니다.

## 공격 유형과 대응 { .l2 }

| 공격 | 필요한 접근 | 원리 | 대표 대응 |
|---|---|---|---|
| 전압·클럭 글리치 | 물리 (보드 개조) | 순간 저전압·클럭 왜곡으로 명령을 건너뜀 | 전압·클럭 감시 센서, 이중 검사, 중요 분기 중복 |
| EM·레이저 결함 주입 | 물리 (칩 노출) | 국소 전자기 펄스·빛으로 특정 회로 오동작 | 차폐, 빛 센서, 결함 감지 후 리셋 |
| 전력·EM 부채널 | 물리 (측정 장비) | 연산 중 전력 파형과 키 비트의 상관관계 | 마스킹, 상수 시간 회로, 잡음 삽입 |
| 캐시 타이밍 | 같은 칩에서 코드 실행 | 캐시 적중·실패 시간 차로 접근 주소 추측 | 상수 시간 코드, 캐시 분할, 보안 세계 캐시 정리 |
| Spectre 계열 | 같은 칩에서 코드 실행 | 투기 실행이 남긴 캐시 흔적으로 비밀 유출 | 분기 예측기 격리(CSV2), 투기 장벽, 커널 완화 |
| Rowhammer | 같은 칩에서 코드 실행 | 한 DRAM 행을 반복 접근해 이웃 행 비트 반전 | TRR·RFM 등 DRAM 측 완화, 보안 데이터 분리 배치 |
| JTAG·디버그 포트 | 물리 | 디버그로 레지스터·메모리 직접 접근 | 출하 시 디버그 퓨즈, 인증 디버그 |

## 메모리 안전 완화 기능 { .l2 }

| 기능 | 무엇을 막나 | 방식 |
|---|---|---|
| PAC | 반환 주소·함수 포인터 위조 (ROP 등) | 포인터 상위 비트에 키 기반 서명을 넣고 사용 전 확인 |
| BTI | 함수 중간으로 점프하는 코드 재사용 (JOP) | 간접 분기는 `BTI` 표시가 있는 위치로만 허용 |
| MTE | 버퍼 넘침, 해제 후 사용 | 16바이트마다 4비트 태그를 두고 포인터 태그와 비교 |
| CCA | 하이퍼바이저·호스트가 VM 메모리를 보는 것 | Realm 세계와 물리 메모리 소유권 검사 |

MTE의 동기 모드는 잘못된 접근을 즉시 잡지만 성능 비용이 크고, 비동기 모드는 비용이 작지만 보고가 늦습니다. Android는 개발·테스트용 설정과 일부 보안 강화 모드에서 MTE를 쓰기 시작했으며, Pixel 8(Tensor G3)이 개발자 옵션으로 MTE를 처음 노출한 대표 사례입니다([메모리 보호와 IOMMU](../memory/iommu.md)).

??? expert "전문가 노트 — 결함 주입 대응 설계, 투기 실행과 완화의 한계, Rowhammer와 LPDDR, 디버그 잠금"
    **결함 주입 대응 설계.** 부트 ROM의 서명 검사는 "비교 결과가 성공이면 점프"라는 몇 개의 명령으로 끝나므로, 정확한 순간에 한 번의 글리치로 건너뛸 수 있습니다. 대응은 회로와 코드 양쪽에서 합니다. 회로 쪽은 전압·클럭 감지기로 비정상을 감지하면 리셋하고, 코드 쪽은 성공 값을 0/1이 아닌 해밍 거리가 먼 상수로 두고, 같은 검사를 두 번 이상 다른 경로로 반복하며, 무작위 지연을 넣어 타이밍을 맞추기 어렵게 합니다.

    **투기 실행 완화의 한계.** Arm 코어는 CSV2(분기 예측 문맥 분리), `SB`·`CSDB` 장벽, SSBS(투기적 저장 우회 제어) 같은 기능으로 Spectre 변형을 줄이고, 커널은 코어별로 필요한 완화를 골라 켭니다. 그러나 PAC 서명을 투기 실행으로 추측하는 PACMAN(2022, Apple M1 대상), MTE 태그를 투기 실행으로 알아내는 연구(2024)처럼, 완화 기능 자체가 투기 실행의 새 표적이 되는 사례가 보고되었습니다. PAC·MTE는 공격 비용을 크게 높이는 확률적 방어로 보는 것이 정확합니다.

    **Rowhammer와 LPDDR.** 2016년 Drammer 연구가 Android 기기의 LPDDR에서도 Rowhammer로 권한 상승이 가능함을 보였습니다. DRAM이 미세해질수록 이웃 행 간섭이 커져 한계 접근 횟수가 줄어드는 경향이 있으며, 메모리 칩 내부의 표적 리프레시(TRR)와 LPDDR5의 RFM 명령처럼 컨트롤러와 DRAM이 협력하는 완화가 들어갔습니다. 다만 TRR의 우회 패턴도 연구되었으므로, TEE·하이퍼바이저 메모리처럼 중요한 영역을 공격자가 제어하는 메모리와 떨어뜨려 배치하는 소프트웨어 방어가 함께 필요합니다([LPDDR](../memory/lpddr.md)).

    **디버그 잠금.** 개발용 칩은 JTAG·SWD로 모든 코어를 멈추고 메모리를 읽을 수 있습니다. 양산 칩은 퓨즈로 디버그를 끄거나, 보안 세계 디버그(SPIDEN)만 따로 끄고, 서명된 디버그 토큰을 제시할 때만 칩 하나의 디버그를 여는 **인증 디버그**를 씁니다. 반품·고장 분석 때 디버그를 다시 여는 절차가 공격 경로가 되지 않도록, 토큰은 칩 고유 ID에 묶고 사용자 데이터 키는 디버그 활성화 시 쓸 수 없게 설계합니다.
