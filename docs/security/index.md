# 보안과 부팅

이 섹션은 전원을 켠 첫 명령부터 앱이 키를 쓰는 순간까지, **SoC가 하드웨어로 지키는 신뢰의 사슬**을 다룹니다. 스마트폰은 결제·생체 인증·업무 데이터·디지털 키를 담고 있어, 운영체제가 뚫려도 핵심 비밀은 지켜야 합니다. 그래서 현대 SoC는 부팅 검증, 격리된 보안 세계(TrustZone), 별도의 보안 프로세서, 하드웨어 키 관리, 하이퍼바이저를 여러 겹으로 쌓습니다. 각 층은 "아래층을 믿을 수 있을 때만 위층을 믿는다"는 같은 원칙을 따릅니다.

!!! basic "신뢰의 사슬 미리 보기"
    보안의 출발점은 **바꿀 수 없는 무언가**입니다. SoC 안의 마스크 ROM 코드와, 출하 때 한 번만 쓰는 퓨즈(OTP)에 새긴 공개 키 해시가 그 역할을 합니다.

    1. **ROM**이 다음 부트로더의 서명을 퓨즈의 키로 확인합니다.
    2. 확인된 부트로더가 다시 그다음 단계(보안 펌웨어, 하이퍼바이저, Android 부트로더)를 확인합니다.
    3. Android 부트로더가 커널과 시스템 파티션을 확인하고, 그 결과(잠금 상태·검증 상태)를 TEE의 키 관리 기능에 넘깁니다.

    줄줄이 이어진 열쇠 꾸러미처럼, 첫 열쇠가 진짜이고 각 열쇠가 다음 자물쇠만 연다면 끝까지 믿을 수 있습니다. 중간에 하나라도 위조되면 그 아래는 모두 의심해야 합니다.

!!! tip "다른 섹션과의 연결"
    장치의 메모리 접근 격리와 MTE의 메모리 측면은 [메모리 보호와 IOMMU](../memory/iommu.md), 예외 레벨(EL0–EL3)과 Arm 아키텍처 버전은 [Arm 아키텍처](../cpu/arm-architecture.md), UFS 인라인 암호화가 붙는 저장장치는 [UFS 저장장치](../memory/ufs.md), 부트로더·TEE가 BSP에서 어디에 놓이는지는 [Android BSP 구조](../software/android-bsp.md)에서 다룹니다.
