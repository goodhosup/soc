# 소프트웨어와 실무

이 섹션은 칩을 **실제로 움직이게 하는 소프트웨어**와, 그 칩을 **재고 비교하고 직접 만져 보는 방법**을 다룹니다. 같은 SoC라도 커널·드라이버·HAL이 얼마나 잘 만들어졌는지, 업데이트를 몇 년 받는지에 따라 기기 경험이 크게 달라집니다. 또 사양표와 벤치마크 점수는 측정 조건을 알고 읽어야 의미가 있으며, 앞 장에서 배운 DVFS·스케줄링·열 관리는 개발 보드 하나로 직접 확인할 수 있습니다.

!!! basic "소프트웨어 스택 미리 보기"
    스마트폰 SoC 위의 소프트웨어는 아래에서 위로 여러 층이 쌓여 있습니다.

    1. **펌웨어와 부트로더** — 전원이 들어오면 가장 먼저 실행되어 DRAM을 초기화하고 커널을 불러옵니다.
    2. **Linux 커널과 드라이버** — CPU·메모리·클럭·전원 같은 하드웨어를 관리합니다. 커널이 하드웨어 구성을 알 수 있도록 **디바이스 트리**가 "이 칩에는 이런 블록이 여기 있다"고 알려 줍니다.
    3. **HAL(하드웨어 추상화 계층)** — 카메라·오디오·센서처럼 칩마다 다른 기능을 Android가 같은 방식으로 부를 수 있게 감싸 줍니다.
    4. **Android 프레임워크와 앱** — 사용자가 보는 부분입니다.

    건물에 비유하면 SoC 벤더는 기초와 배관(커널·드라이버·HAL)을, 스마트폰 제조사는 인테리어(UI·기능)를, Google은 건물 규격(Android와 호환성 요구사항)을 맡습니다.

!!! tip "다른 섹션과의 연결"
    부트로더와 보안 부팅은 [부팅 과정](../security/boot.md), 커널이 클럭과 전압을 바꾸는 원리는 [DVFS와 전력 관리](../power/dvfs.md), 작업을 코어에 배치하는 원리는 [스케줄링과 EAS](../cpu/scheduling.md), 전력을 실제로 재는 방법은 [전력 측정과 분석](../power/measurement.md)에서 다룹니다.
